This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

slop-export moves David's Proton Mail (read through Proton Mail Bridge's local IMAP server) into iCloud Mail. It is a native macOS app (Swift 6, SwiftUI, macOS 14+) with a CLI for headless testing. Read these before any task; they are the source of truth and override anything here:

- `PLAN.md`: phases, Bridge mailbox mapping, acceptance criteria.
- `AUTOPILOT.md`: how agents work unattended, limits (never bypass Proton/Apple security, never handle David's passwords, first real iCloud write needs his go-ahead), which skill to use when.
- `DECISIONS.md`: log every non-obvious choice here (newest on top, never edit old entries).
- `MANUAL-TESTS.md`: steps only David can do; add entries, batch them, keep working against fixtures.

Labels are out of scope (D-001): never read `Labels/*`, never create label folders. Messages only in `All Mail` go to `Unfiled`.

## Commands

The Swift package (core + CLI + tests) builds on Linux and macOS:

```sh
swift build
swift test                                   # unit tests; integration tests skip without fixtures
swift test --filter MailboxPlanTests         # one test class
swift test --filter ProbeIntegrationTests/testWrongCertificateIsRejected
```

Integration tests need the Dovecot fixture servers (`apt-get install dovecot-imapd`; the directory must be traversable by the `dovecot` user, so use something like `/tmp/slopfx`, not a 0700 scratch dir):

```sh
python3 Fixtures/slopfixture.py up --dir /tmp/slopfx      # starts "bridge" (STARTTLS) and "icloud" (TLS)
SLOP_FIXTURE_DIR=/tmp/slopfx swift test
python3 Fixtures/slopfixture.py down --dir /tmp/slopfx
```

Run the CLI against the fixture (passwords come from env vars or the macOS Keychain, never from arguments):

```sh
SLOP_BRIDGE_PASSWORD=fixture-bridge-password swift run slop-export probe \
  --user fixture@example.test --port "$(python3 -c "import json;print(json.load(open('/tmp/slopfx/bridge.json'))['port'])")" \
  --cert /tmp/slopfx/bridge/cert.pem
```

If no Swift toolchain is installed (agent containers), run inside `mirror.gcr.io/library/swift:6.1-noble` with `--network host` and the repo mounted; Docker Hub may rate-limit, the gcr mirror does not.

The app only builds on macOS (CI `macos` job):

```sh
brew install xcodegen swiftlint
cd App && xcodegen generate && cd ..
xcodebuild -project App/SlopExport.xcodeproj -scheme SlopExport -destination 'platform=macOS' test
swiftlint lint
scripts/package-app.sh path/to/SlopExport.app dist     # ad-hoc sign, .zip + .dmg
```

## Architecture

- `Sources/SlopCore`: all logic, no UI. Shared by the app and the CLI.
  - `IMAP/IMAPClient.swift`: an actor on top of swift-nio-imap 0.4.0 (pinned; newer needs macOS 15, D-003). One command in flight at a time, no pipelining. Handles STARTTLS (TLS handler inserted at the front of the pipeline after `OK`) and implicit TLS.
  - `IMAP/ResponseCollector.swift`: NIO handler under the client. Matches tagged responses to the in-flight command, collects untagged data, assembles streamed FETCH bodies into `FetchRecord`s, enforces per-command timeouts.
  - TLS trust: Bridge uses `.pinned` (server leaf DER must equal the exported cert byte for byte, D-004); iCloud uses `.system`.
  - `MailboxPlan.swift`: maps each Bridge mailbox to a role (export target, All Mail, Starred-as-flag, skipped label, container). Custom folders colliding with iCloud system names go under `Proton Folders/` (D-007).
  - `Secrets.swift`: `SLOP_BRIDGE_PASSWORD` / `SLOP_ICLOUD_PASSWORD` env vars first, then Keychain items with service `slop-export.bridge` / `slop-export.icloud`, account = user name.
  - `Probe.swift`: Phase 1 scan. Fetches metadata only; never reads bodies, never sets flags (`EXAMINE`, `BODY.PEEK`).
- `Sources/slop-export`: thin ArgumentParser CLI (`probe | export | verify | upload`).
- `App/`: SwiftUI app generated by XcodeGen from `App/project.yml` (D-005). Sandboxed (network client, user-selected files). `AppModel` drives the five steps Connect, Scan, Export, Verify, Upload. The Bridge cert is stored as DER bytes in UserDefaults, not as a bookmark (D-008).
- `Fixtures/slopfixture.py`: starts Dovecot as a process with a generated config and a Maildir seeded directly from Python (D-006). The `bridge` corpus mirrors Bridge's layout and advertises only Bridge-like capabilities (no `STATUS=SIZE`, no `QUOTA`), so code paths must not depend on them. Tests read `DIR/<kind>.json` for host, port, user, password, cert. Corpus counts are asserted in tests; update both together.
- CI (`.github/workflows/ci.yml`): `linux` job runs in a `swift` container with fixtures and `SLOP_REQUIRE_FIXTURES=1` (integration tests fail rather than skip); `macos` job lints, builds the universal app, runs UI tests, packages; `release` on `v*` tags attaches `.zip`/`.dmg`.

## Rules specific to this repo

- Never put real mail, credentials or personal data in the repo, tests, logs or CI. Fixtures are synthetic only.
- Proton side is read-only: no STORE, MOVE, EXPUNGE, DELETE, or non-PEEK body fetches against Bridge.
- No arguments that carry passwords; no disabling TLS verification.
